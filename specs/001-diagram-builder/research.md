**Created**: 2025-01-27

## Technology Decisions

### Decision 1: Библиотека для работы с графами

**Decision**: React-Flow (reactflow)

**Rationale**: 
- React-Flow специально разработан для создания интерактивных графов и диаграмм в React
- Поддерживает узлы (nodes) и связи (edges) с направленными стрелками
- Встроенная поддержка drag-and-drop для узлов
- Автоматическое обновление связей при перемещении узлов
- Хорошая производительность для средних графов (50+ узлов)
- Активная поддержка и документация
- Упоминается в конституции проекта как предпочтительное решение

**Alternatives considered**:
- D3.js: Слишком низкоуровневая, требует больше кода для базовой функциональности
- Cytoscape.js: Хорошая библиотека, но менее интегрирована с React
- Кастомное решение: Потребовало бы слишком много времени на разработку базовой функциональности

**Implementation notes**:
- Использовать React-Flow для основного рабочего поля
- Кастомные типы узлов для сущностей, текстовых заметок
- Встроенные возможности для соединений (edges) с направленными стрелками

### Decision 2: Управление состоянием

**Decision**: React Context API + useReducer для централизованного состояния схемы

**Rationale**:
- Согласно конституции: "Явное управление состоянием (React hooks, Context API или легковесное решение)"
- Context API достаточен для одностраничного приложения без сложной логики
- useReducer обеспечивает предсказуемое управление состоянием для операций с диаграммой
- Избегаем излишних абстракций (принцип конституции)
- Простота важнее переиспользования

**Alternatives considered**:
- Zustand: Легковесная библиотека, но добавляет зависимость без критической необходимости
- Redux: Избыточен для одностраничного приложения
- Локальное состояние компонентов: Недостаточно для синхронизации между компонентами рабочего поля и боковой панели

**Implementation notes**:
- Один Context для состояния диаграммы (DiagramContext)
- useReducer для операций: добавление/удаление/изменение сущностей, соединений, заметок
- Оптимистичные обновления UI (принцип конституции)

### Decision 3: Реализация функции рисования

**Decision**: HTML5 Canvas API с кастомной реализацией

**Rationale**:
- Минимальные зависимости (принцип конституции)
- Canvas API встроен в браузер, не требует дополнительных библиотек
- Достаточно для базовой функциональности рисования
- Можно интегрировать с React-Flow через кастомные слои
- Производительность достаточна для интерактивного рисования

**Alternatives considered**:
- Fabric.js: Мощная библиотека, но избыточна для простого рисования
- Paper.js: Хорошая библиотека, но добавляет зависимость без критической необходимости
- SVG: Может быть сложнее для свободного рисования, лучше для векторной графики

**Implementation notes**:
- Отдельный Canvas слой поверх React-Flow
- Сохранение данных рисования как массив точек/путей
- Интеграция с состоянием диаграммы

### Decision 4: Реализация темной темы

**Decision**: CSS-переменные с переключением через data-атрибут

**Rationale**:
- Соответствует принципу конституции: "Единые дизайн-токены (CSS vars)"
- Все цвета определены через CSS-переменные
- Переключение через изменение data-атрибута на корневом элементе
- Минимальная сложность, без дополнительных библиотек
- Поддержка системной темы через prefers-color-scheme

**Alternatives considered**:
- CSS-in-JS решение: Добавляет зависимость и усложняет структуру
- Отдельные CSS файлы для тем: Дублирование кода, сложнее поддерживать
- Библиотека для тем: Избыточна для простого переключения

**Implementation notes**:
- CSS-переменные для всех цветов в `shared/styles/tokens.css`
- Переключение через `data-theme="dark"` на `<html>` или корневом элементе
- Сохранение предпочтения в LocalStorage

### Decision 5: Формат сериализации состояния

**Decision**: JSON с явной схемой типов TypeScript

**Rationale**:
- JSON - стандартный формат, легко читается и отлаживается
- TypeScript типы обеспечивают типобезопасность (принцип конституции)
- Простая сериализация/десериализация
- Совместимость с LocalStorage и экспортом/импортом файлов
- Минимальная сложность

**Alternatives considered**:
- Бинарный формат: Избыточен, усложняет отладку
- Специализированные форматы (YAML, TOML): Не дают преимуществ для данного случая
- GraphML/другие форматы диаграмм: Избыточны, не соответствуют простоте проекта

**Implementation notes**:
- Типы для Diagram, Entity, Connection, TextNote, Drawing
- Функции serialize/deserialize с валидацией
- Версионирование формата для будущей совместимости

---

### Decision 6: Хранение данных

**Decision**: LocalStorage для автоматического сохранения, File API для экспорта/импорта

**Rationale**:
- LocalStorage достаточен для локального хранения в браузере
- Автоматическое сохранение при изменениях (optimistic UI)
- Экспорт/импорт через File API для переноса между браузерами
- Простота реализации, без дополнительных зависимостей
- Соответствует требованию "опциональное локальное сохранение"

**Alternatives considered**:
- IndexedDB: Избыточен для простых схем, сложнее в использовании
- Серверное хранилище: Не требуется в первой версии
- Cloud storage: Не требуется, приложение полностью клиентское

**Implementation notes**:
- Автосохранение в LocalStorage при каждом изменении
- Кнопка экспорта для скачивания JSON файла
- Кнопка импорта для загрузки JSON файла
- Обработка ошибок при нехватке места в LocalStorage

## Design Patterns

### Паттерн 1: Optimistic UI Updates

**Применение**: Все операции с диаграммой (создание, удаление, изменение) применяются немедленно в UI, затем синхронизируются с состоянием и LocalStorage.

**Rationale**: Соответствует принципу конституции "Optimistic UI с откатом". Создает ощущение мгновенного отклика.

---

### Паттерн 2: Command Pattern для Undo/Redo

**Применение**: Все действия пользователя оборачиваются в команды, которые можно отменить/повторить.

**Rationale**: Реализует требование "прощать ошибки" из спецификации. Позволяет быстро отменить случайные действия.

---

### Паттерн 3: Custom React-Flow Nodes

**Применение**: Создание кастомных типов узлов для сущностей и текстовых заметок, расширяющих базовые возможности React-Flow.

**Rationale**: Позволяет добавить специфичную функциональность (inline-редактирование, кастомный внешний вид) при использовании готовой библиотеки.

---

## Performance Considerations

1. **Виртуализация**: React-Flow автоматически обрабатывает большие графы, но для 50+ узлов может потребоваться оптимизация рендеринга
2. **Debounce для автосохранения**: Сохранение в LocalStorage должно быть отложено (debounce) для избежания частых операций записи
3. **Мемоизация компонентов**: Использование React.memo для узлов и соединений для оптимизации ре-рендеров
4. **Ленивая загрузка**: Режим рисования может быть загружен по требованию

## Accessibility Considerations

1. **Клавиатурная навигация**: Поддержка Tab для навигации, Enter для активации, Delete для удаления
2. **ARIA-метки**: Правильные метки для всех интерактивных элементов
3. **Контрастность**: Цвета должны соответствовать WCAG AA стандартам в обеих темах

## Security Considerations

1. **Валидация импорта**: Проверка структуры JSON при импорте для предотвращения некорректных данных
2. **Sanitization**: Очистка пользовательского ввода в текстовых полях
3. **LocalStorage limits**: Обработка ошибок при превышении лимитов хранилища
